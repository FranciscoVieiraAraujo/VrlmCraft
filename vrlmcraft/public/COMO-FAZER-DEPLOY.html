VRLMCraft Online — Guia de Deploy

Passo a passo visual para colocar seu jogo voxel multiplayer no ar. Escolha o servidor, siga as telas e publique.

~10 minutos de setup • opcao gratis sem complicacao • HTTPS automatico

★ Melhor servidor gratis para subir o jogo

Render.com RECOMENDADO

Para comecar sem dor de cabeca, o Render e a melhor escolha gratis: voce conecta o repositorio do GitHub, ele le o arquivo render.yaml que ja vem no projeto e configura tudo sozinho (build, start, HTTPS e o segredo de sessao). Nao precisa de cartao para o plano Free.

Detalhe importante do plano Free do Render: o servidor “dorme” apos ~15 min sem acesso (acorda sozinho na proxima visita, demora alguns segundos) e nao tem disco permanente — ou seja, os mundos salvos podem se perder num novo deploy. Para o banco nunca se perder, duas saidas: (1) ativar o disco no plano Starter (~US$ 7/mes) ou (2) usar o Fly.io, que oferece volume de disco no modo gratuito. Veja a comparacao abaixo.

Resumo pratico: Render = mais facil para testar/mostrar o jogo. Fly.io = melhor gratis para manter os mundos salvos de verdade. Vercel/Netlify nao funcionam (sem WebSocket nem disco).

0 Pre-requisito: suba o projeto para o GitHub

Quase todos os hosts puxam o codigo direto de um repositorio Git. O projeto ja inclui o script git-setup.sh. No terminal, dentro da pasta do jogo:

git init
git add .
git commit -m "VRLMCraft Online"
git branch -M main
git remote add origin https://github.com/SEU_USUARIO/vrlmcraft-online.git
git push -u origin main
github.com/SEU_USUARIO/vrlmcraft-online

Ilustracao: o repositorio no GitHub com os arquivos do jogo enviados.

Troque SEU_USUARIO pelo seu usuario real do GitHub. Crie o repositorio vazio antes (sem README) para o push funcionar.

1 Escolha o servidor e siga as telas

Render mais facil
Fly.io melhor p/ salvar
Railway alternativa
VPS proprio avancado
Render • Passo 1 de 4

Criar conta e novo Blueprint

Entre em render.com, crie a conta (pode usar “Sign in with GitHub”) e clique em New → Blueprint.

dashboard.render.com

No menu New, escolha Blueprint — e ele que le o render.yaml do projeto.

Render • Passo 2 de 4

Conectar o repositorio do jogo

Autorize o Render a acessar o GitHub e selecione o repo vrlmcraft-online. Ele detecta o render.yaml e mostra o servico ja montado.

dashboard.render.com/blueprints/new

O render.yaml ja traz build, start, o disco persistente e o segredo — nao precisa digitar nada.

Se quiser o jogo 100% gratis, mude o plano do servico para Free. Mas lembre: no Free o disco em /var/data nao e mantido. Para salvar mundos de verdade, deixe no Starter (com disco) ou va de Fly.io.
Render • Passo 3 de 4

Apply / Deploy

Clique em Apply. O Render instala, builda e sobe o servidor. Acompanhe os logs ate aparecer Servidor ouvindo....

dashboard.render.com/web/vrlmcraft-online/logs

Quando aparece “Live” em verde, o jogo esta no ar.

Render • Passo 4 de 4

Abrir a URL publica

No topo da pagina do servico aparece a URL (ja com HTTPS), algo como https://vrlmcraft-online.onrender.com. Abra e jogue!

https://vrlmcraft-online.onrender.com

O jogo rodando no navegador pela URL publica. Compartilhe esse link com os amigos.

Pronto! Teste criar conta, salvar um mundo, sair e entrar de novo. Se o mundo continuar la, o banco esta funcionando.
Fly.io • Passo 1 de 4

Instalar o Fly CLI e logar

Melhor opcao gratis com disco permanente. Instale o CLI e faca login:

# Windows (PowerShell)
iwr https://fly.io/install.ps1 -useb | iex
# Mac/Linux
curl -L https://fly.io/install.sh | sh

fly auth signup   # ou: fly auth login
O Fly pede um cartao apenas para verificacao anti-abuso — o uso dentro das franquias gratuitas (VM pequena + volume de 1-3GB) nao gera cobranca.
Fly.io • Passo 2 de 4

Lancar o app

Na pasta do jogo (ele ja tem o fly.toml):

fly launch --no-deploy   # recuse bancos gerenciados; mantem o fly.toml
terminal — fly launch
Fly.io • Passo 3 de 4

Criar o volume e o segredo

O volume e o disco onde os mundos ficam salvos. O segredo protege as sessoes:

fly volumes create vrlmdata --size 1 --region gru
fly secrets set SESSION_SECRET=$(openssl rand -hex 24)
Com volume criado, os mundos salvos persistem entre deploys — por isso o Fly e o melhor gratis para o jogo “de verdade”.
Fly.io • Passo 4 de 4

Deploy

fly deploy

Ao terminar, a URL sera https://vrlmcraft-online.fly.dev (com HTTPS). Rode fly open para abrir no navegador.

Pronto! Mesmo teste: crie conta, salve mundo, saia e volte — deve continuar la.
Railway • Passo 1 de 4

Novo projeto a partir do GitHub

Em railway.app, clique em New Project → Deploy from GitHub repo e escolha o repo. Ele usa o Dockerfile (configurado no railway.json).

Railway • Passo 2 de 4

Definir as variaveis

Em Variables, adicione:

DB_FILE=/data/vrlmcraft.db
SESSION_SECRET=<uma chave aleatoria longa>
EVENT_HOUR=19
EVENT_MINUTE=30
Railway • Passo 3 de 4

Criar o volume

Em Settings → Volumes, crie um volume e monte em /data (o mesmo caminho de DB_FILE). E ai que os mundos salvos ficam guardados.

Railway • Passo 4 de 4

Gerar o dominio

Em Settings → Networking → Generate Domain, pegue a URL publica com HTTPS e abra o jogo.

O Railway da um credito gratis de teste; depois dele o uso continuo passa a ser cobrado. Para 100% gratis sem prazo, prefira Render (testar) ou Fly.io (persistente).
VPS • Passo 1 de 3

Preparar a maquina

Instale Node.js 18+ e envie os arquivos. Depois:

npm install
cp .env.example .env     # edite PORT, SESSION_SECRET, DB_FILE
npm start
VPS • Passo 2 de 3

Manter rodando sempre (systemd)

Crie /etc/systemd/system/vrlmcraft.service e ative:

[Service]
WorkingDirectory=/opt/vrlmcraft
ExecStart=/usr/bin/node server.js
Environment=PORT=15800
Environment=DB_FILE=/opt/vrlmcraft/db/vrlmcraft.db
Environment=SESSION_SECRET=TROQUE_ISSO
Restart=always

sudo systemctl enable --now vrlmcraft

Alternativa simples: npm i -g pm2 && pm2 start server.js.

VPS • Passo 3 de 3

HTTPS com Nginx + certbot

Ponha o Nginx como proxy (precisa repassar o WebSocket /ws) e gere o certificado:

proxy_pass http://127.0.0.1:15800;
proxy_http_version 1.1;
proxy_set_header Upgrade $http_upgrade;
proxy_set_header Connection "upgrade";

sudo certbot --nginx
Sem HTTPS o chat de voz (microfone) e o WebSocket podem ser bloqueados pelo navegador. HTTPS e obrigatorio.

2 Conferir se deu tudo certo

  • Acesse https://SEU-DOMINIO/api/health → deve responder {"ok":true}.
  • Crie uma conta, salve um mundo, saia e entre de novo — o mundo precisa continuar la (prova do disco/banco).
  • Abra em dois navegadores diferentes e entre no mesmo mundo para testar o multiplayer e o chat de voz.
Seguranca: rode sempre atras de HTTPS, use um SESSION_SECRET aleatorio e longo, e guarde os segredos apenas no painel do host (nunca dentro do codigo no GitHub).
